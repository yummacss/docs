## Run It

`yummaui` copies component files into your project & is never a dependency.

```bash
pnpm dlx yummaui <command>
```

The examples use `pnpm dlx`. `init` & `add` print the runner your project uses: `npx`, `yarn dlx` or `bunx`.

## Set Up a Project

Writes `yummaui.json`. It detects your framework, package manager & import alias, then asks where components live: `src/components/ui`, or `components/ui` without a `src` folder.

```bash
pnpm dlx yummaui init
```

Without Yumma CSS, `init` offers to set it up:

- installs `yummacss` & its Vite or PostCSS plugin, and registers it
- writes `yumma.config.mjs` with what the components animate with
- adds `@yummacss;` to your stylesheet

Where a file cannot be changed safely, it prints the line to add.

| Option      |                                    |
| ----------- | ---------------------------------- |
| `--force`   | Replace an existing `yummaui.json` |
| `-y, --yes` | Skip prompts & take the defaults |

## Add Components

Copies one or more components in. With no names, it opens a list to search & pick from.

```bash
pnpm dlx yummaui add button
pnpm dlx yummaui add dialog tooltip
pnpm dlx yummaui add
pnpm dlx yummaui add --all
pnpm dlx yummaui add button --style compact --radius small
```

| Option            |                                               |
| ----------------- | --------------------------------------------- |
| `-a, --all`       | Add every component                           |
| `--style <name>`  | `soft`, `compact` or `squircle`               |
| `--radius <step>` | `none`, `small`, `medium`, `large` or `extra` |
| `--overwrite`     | Replace files that already exist              |
| `-y, --yes`       | Skip prompts & take the defaults            |

It asks before installing what a component needs from npm, and offers the same Yumma CSS setup as `init` when it is missing.

## List Components

```bash
pnpm dlx yummaui list
```

Prints every component.

## Remove Unused Components

Finds component files nothing in your project reaches.

```bash
pnpm dlx yummaui prune
pnpm dlx yummaui prune --write
```

| Option      |                                 |
| ----------- | ------------------------------- |
| `--write`   | Delete, instead of only listing |
| `-y, --yes` | Skip the confirmation           |

<Hint icon="info">
  Only files `add` wrote are ever candidates. Your own components in the same
  folder are never touched.
</Hint>

A file counts as used only when something **outside** your components directory reaches it, so an unused chain of components goes together. Deleting takes `--write` & a confirmation.

## Configuration File

```json title="yummaui.json"
{
  "componentsDir": "src/components/ui",
  "alias": "@/components/ui",
  "registry": "https://yummacss.com/ui/registry"
}
```

| Field           | Meaning                                                                 |
| --------------- | ----------------------------------------------------------------------- |
| `componentsDir` | Where components are written, relative to the project root              |
| `alias`         | The import prefix for that directory, or `null` to use relative imports |
| `registry`      | Where components are fetched from                                       |
| `style`         | The style `add` uses when `--style` is not given                        |
| `radius`        | The radius `add` uses when `--radius` is not given                      |

## Registry

The registry is static JSON published by this site.

```
https://yummacss.com/ui/registry/index.json                     every component, and the theme they animate with
https://yummacss.com/ui/registry/<id>.json                      one component's source and dependencies
https://yummacss.com/ui/registry/styles.json                    the styles and the radius steps each takes
https://yummacss.com/ui/registry/<style>-<radius>/<id>.json     the same, rewritten for a style
```

Point `registry` at your own copy to serve components from somewhere else.
