### Resolved

- **#7 deferred.** `@` means "compiles to an `@media` wrapper" (`@sm`, `@pc`).
  That is only honest if the variant compiles to
  `@media (prefers-color-scheme: dark)` - but the useful behaviour is
  following a manual toggle, which is a selector, not an at-rule. Since the
  token layer already handles both OS preference & manual toggle via
  `color-scheme`, the escape hatch is not needed yet. Design it when a real
  case appears; that case will also settle the notation.
- **#11 dropped.** `gtc-1` … `gtc-16` already generate
  `repeat(N, minmax(0, 1fr))`, and `gtc-s` / `gtr-s` already generate
  `subgrid`. A `fr` variant would differ from `gtc-1` only in `1fr` vs
  `minmax(0, 1fr)` - a real difference in shrink behaviour, but two
  near-identical classes is a footgun & `minmax(0, 1fr)` is usually wanted.
- **#15 rejected.** Clean break, no dual-syntax parser. The user base is one
  person who will be migrated by hand. The codemod (#12) is still required.
- **`subtle` token contrast.** Measured against the real gray scale, no single
  value passes AA in both schemes: `gray-6` is 3.66 on white, `gray` is 3.88
  on `gray-12`. Resolved by making it a pair like every other token -
  `light-dark(gray, gray-6)` gives 4.83 light / 5.13 dark, both passing, & it
  still sits below `muted` (6.13 / 6.56) in the hierarchy.

- **#6b rejected.** No built-in `page` / `surface` / `fg` vocabulary. Dark mode
  is opt-in per color: every utility color applies in both schemes as it always
  has, & a user who wants a specific color to differ in dark mode defines it as
  a pair. Shipping 11 opinionated names would claim namespace & impose a design
  system on people who only wanted one color to change. The token table from
  the earlier draft is still a sound recipe - it belongs in the docs as an
  example, not in core.
- **#13 needs no work.** Verified against a running `next dev`: editing
  `yumma.config.mjs` propagates to the served CSS in roughly ten seconds with
  no source file touched & no restart. `loadConfig` busts the ESM import cache
  with the file's mtime, & the PostCSS plugin registers the config path as a
  `dependency` message, so Turbopack watches it. Both landed in 3.26.

  Debugging note: dev CSS is minified, so `#ff00ff` is served as `#f0f`. Use a
  color that cannot be shortened to three digits when grepping generated
  output, or the change looks like it never happened.
- **#16 OKLCH, deferred to 4.0.** Shades are mixed toward white & black in
  sRGB. Hue holds up well - under 10 degrees of drift across every default hue
  - but lightness spacing collapses on light-native hues. Measured spread
  between the largest & smallest step: blue 23%, red 103%, magenta 160%,
  cyan 226%, lime 261%, **yellow 460%**. So `yellow-1` through `yellow-6` are
  nearly indistinguishable while the dark end plummets. OKLCH fixes this, but
  it changes every generated color value, which is major-only. `tinycolor2`
  cannot parse `oklch()` or `lch()` at all, so it also needs a new colour
  library or hand-rolled matrices. Shade generation is now isolated inside
  `generateShades` so the swap stays contained.
- **#17 rejected.** Renaming shades to 50/100/200 imports the identity 4.0
  exists to move away from, breaks every class name, grows the codemod, and
  renders nothing differently. The current 1-12 scale with an unnumbered base
  at the midpoint is monotonic & works.

## Post draft

Everything below is prose for the published post. Sections stay commented out
until the feature actually ships.

Yumma CSS 4.0 changes how every utility is written. `-` becomes `:` between a
property & its value, which makes the class a compressed form of the
declaration it generates.

```html del={1} ins={2}
<div class="d-f jc-c ai-c"></div>
<div class="d:f jc:c ai:c"></div>
```

The rule is one line: `:` separates property from value, `-` subdivides a value.

```html
<div class="bg:gray-1 c:blue-4"></div>
```

Negative values stop being a special case. `m--4` was a parser artifact leaking
into the API - `m:-4` is the declaration with the whitespace removed.

```html del={1} ins={2}
<div class="m--4"></div>
<div class="m:-4"></div>
```

Variants keep their prefix position. `h:bg:gray-1` groups & sorts predictably,
& `h:` stays greppable.
