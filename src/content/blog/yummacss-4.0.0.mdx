### Open questions

- **`subtle` token in light mode.** `gray-6` on white measures 3.66:1 - passes for
  large text only, fails AA for body. Bump it, or document it as
  placeholder/decorative only?
- **`@d:` semantics.** Compile to `@media (prefers-color-scheme: dark)` (follows
  the OS, ignores a manual toggle) or to `[data-theme="dark"]` (follows the
  toggle, ignores the OS)? One selector cannot do both. Tokens are unaffected -
  they work correctly either way.
- **Compat mode (#15).** Accepting v3 & v4 syntax simultaneously for one release
  turns the migration from a cliff into a ramp. Worth the parser complexity?

### Knock-on work outside the monorepo

- `intellisense-vscode` & `intellisense-zed` - class-detection patterns assume
  the v3 shape & will not match `d:f`.
- `eclipsa-vscode` & `eclipsa-zed` - unaffected, but worth a pass.
- `@yummacss/canon` - the canon list is what AI tools & `validate()` check
  against; it has to ship with v4 or every v4 class reads as unknown.
- `docs` - every code example. Run the codemod here first; it is the largest
  real corpus & has to be migrated anyway.

## Post draft

Everything below is prose for the published post. Sections stay commented out
until the feature actually ships.

Yumma CSS 4.0 changes how every utility is written. `-` becomes `:` between a
property & its value, which makes the class a compressed form of the
declaration it generates.

```html del={1} ins={2}
<div class="d-f jc-c ai-c"></div>
<div class="d:f jc:c ai:c"></div>
```

The rule is one line: `:` separates property from value, `-` subdivides a value.

```html
<div class="bg:gray-1 c:blue-4"></div>
```

Negative values stop being a special case. `m--4` was a parser artifact leaking
into the API - `m:-4` is the declaration with the whitespace removed.

```html del={1} ins={2}
<div class="m--4"></div>
<div class="m:-4"></div>
```

Variants keep their prefix position. `h:bg:gray-1` groups & sorts predictably,
& `h:` stays greppable.
