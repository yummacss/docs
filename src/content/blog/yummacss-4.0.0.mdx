### Why the Colon, in One Place

The point of 4.0 is to close the distance to vanilla CSS. `d:f` reads as
`display: flex` with the whitespace removed; `d-f` does not read as anything.
The colon is the separator CSS already uses, so the notation stops looking
borrowed from anywhere and starts looking like what it is.

The scope is deliberately narrow. Only the property/value separator changes:

- `d-f` -> `d:f`, `ta-c` -> `ta:c`
- `bg-red-1` -> `bg:red-1`. **Shades keep the dash.** `bg:red:1` reads as three
  levels of nesting when it is really one value with a step.
- `h:bg-white` stays exactly as it is. Variants remain a prefix, because
  `bg-white:h` puts the condition after the thing it conditions.
- Naming is always the full package name: `pnpm dlx yummacss migrate`, matching the
  npm name & the URL. Never `pnpm dlx yumma`.

Container queries (#10) ship in **4.0**, not a later minor. They change how
media queries compile, so holding them for 4.1 would mean a second breaking
release weeks after the first.

### Resolved

- **#7 deferred.** `@` means "compiles to an `@media` wrapper" (`@sm`, `@pc`).
  That is only honest if the variant compiles to
  `@media (prefers-color-scheme: dark)`, but the useful behavior is
  following a manual toggle, which is a selector, not an at-rule. Since the
  token layer already handles both OS preference & manual toggle via
  `color-scheme`, the escape hatch is not needed yet. Design it when a real
  case appears; that case will also settle the notation.
- **#11 dropped.** `gtc-1` … `gtc-16` already generate
  `repeat(N, minmax(0, 1fr))`, & `gtc-s` / `gtr-s` already generate
  `subgrid`. A `fr` variant would differ from `gtc-1` only in `1fr` vs
  `minmax(0, 1fr)`, a real difference in shrink behavior, but two
  near-identical classes is a footgun & `minmax(0, 1fr)` is usually wanted.
- **#15 rejected.** Clean break, no dual-syntax parser. The user base is one
  person who will be migrated by hand. The codemod (#12) is still required.
- **`subtle` token contrast.** Measured against the real gray scale, no single
  value passes AA in both schemes: `gray-6` is 3.66 on white, `gray` is 3.88
  on `gray-12`. Resolved by making it a pair like every other token -
  `light-dark(gray, gray-6)` gives 4.83 light / 5.13 dark, both passing, & it
  still sits below `muted` (6.13 / 6.56) in the hierarchy.

- **#6b rejected.** No built-in `page` / `surface` / `fg` vocabulary. Dark mode
  is opt-in per color: every utility color applies in both schemes as it always
  has, & a user who wants a specific color to differ in dark mode defines it as
  a pair. Shipping 11 opinionated names would claim namespace & impose a design
  system on people who only wanted one color to change. The token table from
  the earlier draft is still a sound recipe. It belongs in the docs as an
  example, not in core.
- **#13 needs no work.** Verified against a running `next dev`: editing
  `yumma.config.mjs` propagates to the served CSS in roughly ten seconds with
  no source file touched & no restart. `loadConfig` busts the ESM import cache
  with the file's mtime, & the PostCSS plugin registers the config path as a
  `dependency` message, so Turbopack watches it. Both landed in 3.26.

  Debugging note: dev CSS is minified, so `#ff00ff` is served as `#f0f`. Use a
  color that cannot be shortened to three digits when grepping generated
  output, or the change looks like it never happened.

- **#16 OKLCH, deferred to 4.0.** Shades are mixed toward white & black in
  sRGB. Hue holds up well, under 10 degrees of drift across every default hue, but
  lightness spacing collapses on light-native hues. Measured spread
  between the largest & smallest step: blue 23%, red 103%, magenta 160%,
  cyan 226%, lime 261%, **yellow 460%**. So `yellow-1` through `yellow-6` are
  nearly indistinguishable while the dark end plummets. OKLCH fixes this, but
  it changes every generated color value, which is major-only. `tinycolor2`
  cannot parse `oklch()` or `lch()` at all, so it also needs a new color
  library or hand-rolled matrices. Shade generation is now isolated inside
  `generateShades` so the swap stays contained.
- **#20 decided: drop pseudo-class stacking, keep everything else.** Measured
  against the generator rather than argued from taste. Every stack compiles
  correctly today & order in the chain is irrelevant, since each prefix is
  resolved by what it is: `@sm:h:bg-red` & `h:@sm:bg-red` produce the same rule.
  The combinations worth keeping all pair _different kinds_ of condition -
  `@sm:h:` (media + state), `h:s::` (state + pseudo element), `@sm:s::`, & any
  of those plus an opacity suffix. Two pseudo classes are the one case that
  pairs a kind with itself, and it compiles to a both-at-once selector:
  `f:h:bg-red` is `:focus:hover`, matching only an element focused **and**
  hovered simultaneously. Nobody wants that; they want either state to trigger,
  which is two utilities.

  Dropping it is free. A scan of every real corpus - `docs/src`, the 450-file
  registry, `play/src` - found **zero** uses, there are **no tests** covering
  it, and it appears in no documentation. So there is nothing to migrate, no
  test to delete, and no codemod case to write. It removes parser surface at
  genuinely zero cost.

  Removal is 4.0 only. It is unused & undocumented, but stripping it from the v3
  parser would still be a breaking change shipped in a patch.

- **#22 decided.** [Naming Convention](/docs/naming-convention) already tells
  readers that `none` & `auto` are never abbreviated, and names these two as
  the exceptions that change in 4.0. The rule was on the site before it was in
  this table, so this row records what the page already promises. `tt-n` reads
  as nothing at all, & the codemod rewrites both.
- **#23 decided: `theme.fonts`.** `theme` takes `colors` & `screens`, so a
  project's palette & breakpoints are first-class, but there is no font entry.
  That is why the docs site defines `.ff-e` as hand-written CSS in
  `globals.css` rather than configuring Esteban: the class works, it is simply
  not a generated one, so canon reports it & every consumer has to allowlist
  it.

  A record keyed the way `colors` is, where the key becomes the value after
  the colon:

  ```js title="yumma.config.mjs"
  export default defineConfig({
    theme: {
      fonts: {
        e: ["Esteban", "serif"],
        m: ["iA Writer Quattro", "sans-serif"],
      },
    },
  });
  ```

  Each key generates `ff:<key>`, so `ff:e` becomes
  `font-family: "Esteban", serif`. An array is the stack in order & a string
  is a one-entry stack. Keys replace the defaults they collide with rather
  than merging, which is what `colors` already does.

  No shade-equivalent behavior: a font has no scale to derive, so unlike a
  color it generates exactly one utility per key.

  The migration is the acceptance test. `.ff-e` comes out of `globals.css` &
  goes into the config, and if the docs site cannot drop that rule the feature
  is not finished. Two places have to learn the entry at the same time: the
  codemod, or `ff-e` is skipped during the rewrite, and canon, or it reports
  the class the config just legitimized.

- **#21 decided: warn.** Two stacked media queries silently lose all but the
  last. `@sm:@lg:bg-red` compiles to `@media (min-width: 64rem)` with `@sm`
  discarded & no warning. It is arguably reasonable, since two `min-width` bounds describe one range,
  but the silence is the problem, since the class name says
  something the CSS does not do. Natural home is the #14 unknown-utility warning
  work, and canon should probably flag it too. Documented as a footgun in
  [Nested Variants](/docs/nested-variants) in the meantime.
- **#17 rejected.** Renaming shades to 50/100/200 imports the identity 4.0
  exists to move away from, breaks every class name, grows the codemod, &
  renders nothing differently. The current 1-12 scale with an unnumbered base
  at the midpoint is monotonic & works.

## What's New in v4.0

v4.0 changes how every utility is written. `-` becomes `:` between a property &
its value, which makes the class a compressed form of the declaration it
generates.

```tsx del={1} ins={2}
<div className="d-f jc-c ai-c"></div>
<div className="d:f jc:c ai:c"></div>
```

The rule is one line: `:` separates property from value, `-` subdivides a value.

```tsx
<div className="bg:gray-1 c:blue-4"></div>
```

Negative values stop being a special case. `m--4` was a parser artifact leaking
into the API: `m:-4` is the declaration with the whitespace removed.

```tsx del={1} ins={2}
<div className="m--4"></div>
<div className="m:-4"></div>
```

Variants keep their prefix position. `h:bg:gray-1` groups & sorts predictably,
& `h:` stays greppable.
