## Install the Skill

An agent that loads skills, such as Claude Code, gets Yumma CSS & Yumma UI in one:

```bash
npx skills add yummacss/yummacss
```

It reads these rules from this site each time, so it never goes stale.

## Add It to a Project

Save [agents.md](/agents.md) as the instructions file your agent reads. Most read `AGENTS.md` at the project root.

```bash
curl -s https://www.yummacss.com/agents.md >> AGENTS.md
```

In PowerShell:

```powershell
irm https://www.yummacss.com/agents.md | Add-Content AGENTS.md
```

`>>` & `Add-Content` append, so instructions already in the file stay.

Claude Code reads `CLAUDE.md`. A `CLAUDE.md` holding this one line brings the rules in:

```md title="CLAUDE.md"
@AGENTS.md
```

Other agents that read a file of their own name take the same pointer, or the rules saved there instead.

## What It Covers

| Section | Contents |
| --- | --- |
| Migrating From 3.x | How to tell a 3.x project, and the codemod to run before anything else. |
| Syntax | Property & value initials joined by a colon, variants, opacity, negatives & CSS functions. |
| Values | The spacing scale, every color family & its shades, breakpoints, states & pseudo-elements. |
| Examples | Four Yumma UI components to read before building something similar: Button, Field, Tabs & Dialog. |
| Check | Run `yummacss lint` after editing & use its suggestion, plus the Oxlint rules where a project lints. |

The lists come from the same tables the generator reads, so the file always matches the current release.

## Check the Result

The file asks the agent to run the check itself, but it is worth running in CI as well:

```bash
pnpm dlx yummacss lint
```

It exits with `1` when a class does not exist. [Lint](/docs/configuration#lint) covers the command & the Oxlint rules.
