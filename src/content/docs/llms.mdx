Every page here is available as plain text. If you are pointing a coding agent at Yumma CSS, or writing a tool that reads these docs, nothing needs scraping.

## The Routes

| Route | What it returns |
| --- | --- |
| [`/llms.txt`](/llms.txt) | An index. Every page with its one-line description, grouped the way the sidebar is. |
| [`/llms-full.txt`](/llms-full.txt) | Every docs & component page concatenated in full. |
| `/docs/<slug>.md` | A single docs page as markdown, e.g. [`/docs/display.md`](/docs/display.md). |
| `/ui/components/<slug>.md` | A single component page as markdown. |

Each page also carries a **View as markdown** link in its table of contents, which is the same `.md` route.

## Which One To Reach For

**Start with `/llms.txt`.** It is an index, so it is cheap to read & it tells you which page answers the question. Fetch that page's `.md` route & you have the answer without loading anything else.

**`/llms-full.txt` is the whole corpus & runs to roughly a megabyte.** That will not fit in a smaller context window, so it suits indexing or embedding rather than being pasted into a prompt. If you are tempted to attach it, the index plus one page is almost always the better trade.

## What the Markdown Contains

The `.md` routes are generated from the same source the site renders, not scraped from HTML. Components are unwrapped into their markdown equivalent, so nothing is lost & no tags leak through:

- A class reference becomes a real markdown table listing every class, the properties it sets & the value it produces.
- Step-by-step sections become numbered headings.
- Callouts become blockquotes.
- Code fences keep their language & their filename.

## Verify Before You Ship

A class name that looks plausible is not necessarily real, & the failure is quiet: an unknown class generates no CSS rather than an error. Check the output:

```bash
npx @yummacss/canon
```

Canon validates against the generator itself, so it is authoritative on whether a class exists & it suggests the closest match when one does not. See [Canon](/docs/canon) for the full surface.

Two habits worth keeping. **Do not assume a Tailwind class name has a Yumma CSS equivalent**, because the naming systems are unrelated. And prefer checking over guessing, since canon is faster than a wrong answer.

## The One Rule Worth Learning

Class names are derived from CSS itself rather than invented. The prefix is the initials of the property & the suffix is the initials of the value:

```text
justify-content: space-between   ->   jc-sb
display: flex                    ->   d-f
text-align: center               ->   ta-c
```

Knowing that, most of the library is derivable rather than memorised. Variants are prefixes on top of it, so `h:bg-red` is a hover state & `@sm:d-f` is a breakpoint. See [Nested Variants](/docs/nested-variants) for how they stack.
